# Infrastructure

Terraform for the Azure side of the project: a virtual network, Azure Container Registry (ACR) and an AKS cluster.

## Layout

```
infra/
├── scripts/
│   └── Bootstrap-TerraformBackend.ps1   # creates the state storage, writes backend.hcl
├── modules/                             # reusable building blocks, no hard-coded values
│   ├── network/                         # VNet + subnets
│   ├── container-registry/              # ACR + AcrPush role assignments
│   ├── aks/                             # AKS + AcrPull, Network Contributor, cluster admin roles
└── dev-centralindia/                    # a stack: one environment in one region
    ├── versions.tf  providers.tf  variables.tf  main.tf  outputs.tf
    ├── terraform.tfvars                 # ALL names and settings (committed)
    ├── ids.auto.tfvars.example          # template for your IDs (committed)
    ├── ids.auto.tfvars                  # your IDs (git-ignored)
    └── backend.hcl                      # generated by the bootstrap script (git-ignored)
```

## Prerequisites

- Owner (or Contributor + User Access Administrator) on the subscription. The code creates role assignments.
- Terraform 1.9 or later, Azure CLI, and the Az PowerShell modules `Az.Accounts`, `Az.Resources`, `Az.Storage`.

## Deploy from your laptop

```powershell
# 1. Sign in (Azure CLI for Terraform, Az PowerShell for the bootstrap script)
az login
Connect-AzAccount

# 2. Remote state: storage account + backend.hcl
.\infra\scripts\Bootstrap-TerraformBackend.ps1 `
    -SubscriptionId     "<subscription-id>" `
    -ResourceGroupName  "rg-helloaks-tfstate-cin" `
    -StorageAccountName "<globally-unique-name>"

# 3. Your IDs
cd infra\dev-centralindia
Copy-Item ids.auto.tfvars.example ids.auto.tfvars   # then fill it in

# 4. Edit terraform.tfvars: search for "<--"

# 5. Deploy
terraform init -backend-config="backend.hcl"
terraform plan -out tfplan
terraform apply tfplan
```

## Configuration

| File | Committed | Contains |
|------|-----------|----------|
| `terraform.tfvars` | Yes | Every name and setting except IDs |
| `ids.auto.tfvars.example` | Yes | Placeholder template for the IDs |
| `ids.auto.tfvars` | **No** | `tenant_id`, `subscription_id` and principal object IDs, for local runs |
| `backend.hcl` | **No** | Backend settings, generated by the bootstrap script |

In CI the IDs come from GitHub repository variables, passed as `TF_VAR_*`. Terraform loads `*.auto.tfvars` after `terraform.tfvars`, and both override `TF_VAR_*` values, which is why IDs never go in `terraform.tfvars`.

## Cost control

```powershell
az aks stop  -g rg-helloaks-dev-cin -n aks-helloaks-dev-cin   # end of a session
az aks start -g rg-helloaks-dev-cin -n aks-helloaks-dev-cin   # start of the next
```

For longer breaks run `terraform destroy`. The state storage account survives, because Terraform does not manage it.
